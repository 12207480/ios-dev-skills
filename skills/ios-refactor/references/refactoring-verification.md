# 重构验证

## 行为等价性验证方法

### 核心原则

> 重构的定义：在不改变外部可观察行为的前提下，改善代码内部结构。
> 因此，验证的核心就是证明"外部可观察行为没有变化"。

### 自动化测试验证

#### 单元测试

```
验证步骤：
1. 重构前运行完整测试套件，记录结果
2. 重构后运行完整测试套件，对比结果
3. 确保：
   - 通过的测试仍然通过
   - 没有新增失败
   - 测试覆盖率不下降

注意事项：
- 如果测试需要修改（因为内部结构变了），
  必须确认修改后的测试仍在验证相同的外部行为
- 被删除的测试必须有明确理由（如测试的代码已被合并/移除）
```

#### 集成测试

```
关键场景覆盖：
- [ ] 核心业务流程端到端通过
- [ ] 跨模块数据传递正确
- [ ] 错误处理路径正常
- [ ] 边界条件行为一致
```

#### 快照测试（UI 重构场景）

```swift
// 重构前生成基准快照
func testProfileView_snapshot_baseline() {
    let view = ProfileView(user: mockUser)
    assertSnapshot(of: view, as: .image)
}

// 重构后对比快照
// 如果快照不一致，需要确认：
//   - 视觉差异是否可接受？
//   - 是否是预期的改进？
//   - 还是非预期的行为变化？
```

### 手动验证 Checklist

```
当自动化测试不够覆盖时，使用手动验证：

UI 行为验证：
- [ ] 页面布局与重构前一致
- [ ] 所有交互响应正确（点击、滑动、长按）
- [ ] 动画/转场效果一致
- [ ] 状态切换正确（加载中 / 空数据 / 错误 / 正常）
- [ ] 键盘弹出/收起行为正常

数据行为验证：
- [ ] 数据加载正确（正常 / 分页 / 刷新）
- [ ] 数据修改正确（增删改查）
- [ ] 数据持久化正确（退出后再进入）
- [ ] 缓存行为一致

网络行为验证：
- [ ] 正常网络请求/响应正确
- [ ] 弱网/无网络降级正确
- [ ] 超时处理正确
- [ ] 重试逻辑正确
```

### A/B 对比方法

```
截图对比：
1. 重构前对关键页面截图（所有状态变体）
2. 重构后对相同页面截图
3. 逐一对比，标注差异
4. 确认差异是否可接受

日志对比：
1. 重构前记录关键操作的日志输出
2. 重构后执行相同操作，记录日志
3. diff 对比日志输出
4. 分析差异来源
```

## 性能等价性验证

### 基准测试对比

```swift
// 使用 XCTest 性能测试
func testSearchPerformance() {
    let dataset = generateLargeDataset(count: 10000)
    let searchEngine = SearchEngine(data: dataset)

    measure {
        _ = searchEngine.search(query: "测试关键词")
    }
}

// 对比重构前后的结果：
// 重构前：avg: 0.015s, stddev: 0.002
// 重构后：avg: 0.018s, stddev: 0.003
// 差异 20% → 需要调查原因
```

### Instruments 前后对比

```
关键指标对比：

| 指标 | 工具 | 可接受范围 |
|------|------|----------|
| CPU 使用率 | Time Profiler | ±10% |
| 内存峰值 | Allocations | ±5% |
| 内存泄漏 | Leaks | 0 新增泄漏 |
| 帧率（UI） | Core Animation | 保持 60fps/120fps |
| 启动时间 | App Launch | ±5% |
| 磁盘 I/O | File Activity | 无显著增加 |

对比流程：
1. 重构前使用 Instruments 记录关键场景
2. 保存 trace 文件作为基准
3. 重构后对相同场景重新记录
4. 对比关键指标
5. 差异超出可接受范围则需要优化
```

### 常见性能回退原因

```
重构引入的性能问题：
├── 额外的抽象层导致调用开销
│   → 对比是否在热路径上引入了不必要的间接调用
├── Protocol Witness Table 的动态派发
│   → 热路径上考虑使用 @inlinable 或具体类型
├── 状态管理变更导致额外的 UI 刷新
│   → 检查 @Observable / @Published 的通知频率
├── 依赖注入的初始化开销
│   → 确认是否在启动路径上增加了过多对象创建
└── 数据结构变更导致的内存布局差异
    → 对比内存占用和缓存命中率
```

## 回归风险评估

### 评估矩阵

```
对每个修改点评估回归风险：

高风险：
- 修改了被多处调用的公共方法
- 修改了核心数据模型
- 修改了线程/并发相关代码
- 修改了持久化逻辑

中风险：
- 修改了模块内部的方法签名
- 重新组织了文件结构
- 引入了新的抽象层

低风险：
- 重命名局部变量/私有方法
- 提取内联代码为独立方法
- 消除重复代码
```

### 回归测试策略

```
根据风险级别选择回归测试范围：

高风险改动：
  → 运行完整测试套件
  → 手动验证所有调用方
  → 在预发布环境验证

中风险改动：
  → 运行相关模块测试
  → 验证直接调用方
  → 抽样验证关联功能

低风险改动：
  → 运行受影响文件的测试
  → 快速冒烟测试
```

## 重构完成 Checklist

```
代码质量：
- [ ] 重构目标已达成（可读性/可维护性/可测试性提升）
- [ ] 代码遵循项目架构模式和编码规范
- [ ] 无调试代码残留
- [ ] 无注释掉的旧代码（已完全删除）

测试覆盖：
- [ ] 原有测试全部通过（零回归）
- [ ] 测试覆盖率不低于重构前
- [ ] 关键路径有充分的测试覆盖
- [ ] 新增的抽象层有对应的测试

行为等价：
- [ ] 所有外部可观察行为与重构前一致
- [ ] UI 表现一致（截图对比通过）
- [ ] 数据处理逻辑一致
- [ ] 错误处理路径一致
- [ ] 边界条件行为一致

性能等价：
- [ ] 性能基准测试对比通过
- [ ] 无内存泄漏
- [ ] 无帧率下降
- [ ] 无启动时间回退

影响范围：
- [ ] 所有调用方行为正常
- [ ] 关联模块功能正常
- [ ] 构建时间无显著增加
```

## PR 提交规范（重构 PR 的特殊要求）

### PR 标题格式

```
refactor: [重构操作] [重构对象]

示例：
  refactor: 从 OrderViewController 提取 ViewModel
  refactor: 将 UserService 从 ObjC 迁移到 Swift
  refactor: 引入 Repository 协议解耦数据层
  refactor: 将用户模块拆分为独立 SPM Package
```

### PR 描述模板

```markdown
## 重构动机
[为什么要做这次重构？解决什么问题？]

## 重构策略
[使用了什么重构模式/技术？]

## 改动范围
- 修改的文件：[N 个]
- 涉及的模块：[列表]
- 新增的文件：[列表及用途]
- 删除的文件：[列表及原因]

## 行为变更声明
> 本 PR 不包含任何外部行为变更。
> 所有公共接口的输入/输出/副作用与重构前完全一致。

## 等价性验证
- [x] 原有测试全部通过（附截图/链接）
- [x] 测试覆盖率：重构前 X% → 重构后 Y%
- [x] 性能基准测试通过（附对比数据）
- [x] UI 截图对比通过（附截图）

## 注意事项
[Review 时需要特别关注的地方]
```

### 重构 PR 的特殊规则

```
1. 绝不混入功能变更
   → 功能变更另开 PR

2. 粒度适中
   → 一个 PR 做一个重构操作
   → 大型重构拆分为多个 PR 序列

3. 提交历史清晰
   → 每个 commit 是一个原子重构操作
   → commit message 描述重构操作而非代码改动

4. 必须包含等价性验证
   → 没有验证的重构 PR 不应合并
```
