# Issue 分类与信息提取

## Issue 信息提取模板

从 Issue / QA 反馈 / 用户反馈中逐项提取：

### 问题分类（7 大类）

| 分类 | 典型表现 |
|------|---------|
| UI 显示异常 | 布局错乱、颜色不对、文字截断、图片不显示 |
| 功能逻辑错误 | 按钮点击无反应、流程走不通、计算结果不对 |
| 数据问题 | 数据不展示、数据错误、数据丢失、缓存不更新 |
| 交互不符合预期 | 动画异常、手势冲突、导航方向错误 |
| 性能问题 | 卡顿、掉帧、加载慢、耗电 |
| 兼容性问题 | 特定设备/系统版本/语言/深色模式 |
| 崩溃 | 闪退、ANR、Watchdog Kill |

### 预期行为

确认"正确的表现应该是什么"：
- 产品文档/设计稿中是怎么定义的？
- 其他平台（Android/Web）是怎么表现的？
- 上个版本是怎么工作的？

### 实际行为

精确描述现在实际发生了什么：
- 具体现象的精确描述（截图/录屏优先）
- 是完全不工作，还是部分不对？

### 复现条件

- 操作步骤（精确到每次点击）
- 前置条件（数据状态/登录状态/网络状态/权限状态）
- 复现概率（必现/高概率/偶现）
- 受影响范围（所有用户/特定条件下的用户）

## 信息不充分时的追问模板

Issue 描述不清晰是常态。主动追问比猜测高效 10 倍。

**描述不清时：**
- "实际表现是什么？能否提供截图或录屏？"
- "这个问题是什么时候开始出现的？"

**无法复现时：**
- "你的设备型号和 iOS 版本是什么？"
- "操作前是否做过特定操作？（如登录/切换账号/清除缓存）"
- "是 Debug 包还是 TestFlight/App Store 包？"

**预期不明确时：**
- "正确的表现应该是什么？有没有设计稿/PRD 可以参考？"
- "其他平台（Android/Web）上是怎么表现的？"
- "上个正常版本的行为是什么样的？"

## 问题理解卡片模板

读完 Issue 后，用此模板确认理解是否准确：

```
问题理解卡片：

问题：[用自己的话复述问题，不超过两句]
预期：[应该怎样]
实际：[现在怎样]
分类：[UI / 逻辑 / 数据 / 交互 / 性能 / 兼容 / 崩溃]
严重程度：[P0 阻断 / P1 严重 / P2 一般 / P3 轻微]
复现路径：[步骤 1 → 步骤 2 → 步骤 3 → 出现问题]
```

**关键原则：** 如果无法写出清晰的"问题理解卡片"，说明 Issue 还没读懂，不要开始下一步。
