# 修复审查与验证

## 代码自审清单

### 代码正确性
- [ ] 修复确实针对根因，而非症状 `[手动]`
- [ ] 修改逻辑在所有条件下都正确（正常 / 边界 / 异常） `[手动]`
- [ ] 可选值处理安全（无强制解包） `[自动]` SwiftLint `force_unwrapping` 规则
- [ ] 条件分支完整（switch 有 default / if-else 无遗漏） `[自动]` 编译器警告
- [ ] 数组访问有 bounds 检查 `[手动]`

### 代码安全性
- [ ] 闭包中需要的 `[weak self]` 已添加 `[自动]` SwiftLint `retain_cycle` 相关规则
- [ ] 主线程操作已确保在主线程执行 `[自动]` Main Thread Checker
- [ ] 无数据竞争风险（共享可变状态已保护） `[自动]` Thread Sanitizer / `[手动]` 代码审查
- [ ] 敏感数据处理正确（不暴露到日志/UI） `[手动]`

### 代码整洁性
- [ ] 无调试代码残留（print / TODO / 硬编码测试数据） `[自动]` SwiftLint 自定义规则 / `[手动]` diff 审查
- [ ] 修改范围最小化（不含无关改动） `[手动]`
- [ ] 遵循项目现有代码风格 `[自动]` SwiftLint / SwiftFormat
- [ ] 新增代码有必要的注释（解释 WHY，不解释 WHAT） `[手动]`

## 5 层影响范围验证

### 第 1 层：直接验证（必做）
- 按 Issue 中的复现步骤操作 → 问题已消失 `[手动]`
- 按预期行为操作 → 功能正常 `[手动]`
- 测试边界情况 → 不产生新问题 `[手动]`

### 第 2 层：同页面验证（必做）
- 修改涉及的页面上，其他功能是否仍正常？ `[手动]`
- 页面上其他 UI 元素是否受影响？ `[手动]`
- 页面的其他状态（加载中/空/错误/正常）是否正常？ `[手动]`

### 第 3 层：上下游页面验证（必做）
- 从上一个页面进入 → 数据传递正确？ `[手动]`
- 操作后返回上一个页面 → 数据同步正确？ `[手动]`
- 跳转到下一个页面 → 传参正确？ `[手动]`

### 第 4 层：公共组件验证（如改了公共代码）
- 列出所有使用该组件/方法的页面 `[手动]`
- 在每个页面验证修改后的行为是否正常 `[手动]`
- 搜索方式：全局搜索函数名/类名、检查 protocol 的所有 conformance、检查 notification name 的所有 observer、检查 delegate 的所有实现 `[手动]`

### 第 5 层：全量回归（改了核心模块时）
- 运行完整 XCTest 套件 `[自动]` CI
- 运行完整 XCUITest 套件（如有） `[自动]` CI
- 核心流程手动走一遍（登录→主要功能→退出） `[手动]`
