# 关联分析

## 关联关系梳理

从以下维度梳理需求与现有功能的关联：

### 数据关联
- 新增/修改的数据模型，还有哪些页面在使用？
- API 模型修改后，其他接口的 Response 会不会受影响？
- 本地存储的 Schema 变更，需不需要数据迁移？
- 缓存 Key 是否与其他功能共用？

### UI 关联
- 新增入口放在哪个页面？是否影响该页面的现有布局？
- 使用了哪些公共 UI 组件？修改组件是否影响其他页面？
- 样式是否与相邻页面一致？

### 状态关联
- 新增/修改的状态，是否影响其他页面的展示？
- 操作后（如新增/删除/编辑），其他页面需要同步刷新吗？
- 登录/退出/切换账号时，新功能的状态需要重置吗？

### 导航关联
- 新页面插入后，现有的导航流程是否受影响？
- 深度链接/推送通知是否需要支持直达新页面？
- 从不同入口进入新页面，行为是否一致？

### 业务规则关联
- 新增的业务规则是否与现有规则冲突？
- 权限/角色控制是否需要扩展？
- 是否影响已有的埋点/统计逻辑？

## 影响范围评估

### 直接影响（必须处理）
- 需要修改的文件和函数
- 需要新增的文件和函数
- 需要更新的测试用例

### 间接影响（需要验证）
- 共用公共组件/模型的其他页面
- 共用状态的其他功能
- 依赖同一接口的其他逻辑

### 潜在影响（需要关注）
- 性能影响（新增的请求/计算/渲染）
- 包体积影响（新增的资源/依赖）
- 启动速度影响（新增的初始化逻辑）

## iOS 平台检查清单

- [ ] 涉及的 API 在最低支持版本上是否可用？
- [ ] 是否需要新的系统权限？降级方案是什么？
- [ ] 是否涉及 App Store 审核敏感项？
- [ ] 是否需要新的第三方 SDK？（大小/兼容性/隐私合规）
- [ ] 新增代码是否影响启动性能？
- [ ] 数据变更是否需要考虑旧版本兼容？

## 输出模板：关联分析与实现方案

```
关联分析：
  数据关联：[列出相关模型和接口的影响]
  UI 关联：[列出相关页面和组件的影响]
  状态关联：[列出跨页面的状态同步需求]
  导航关联：[列出导航流程的变化]

实现方案：
  改动点清单：
    1. [文件路径] — [改什么] — [为什么]
    2. [文件路径] — [改什么] — [为什么]
    ...

  新增文件：
    1. [文件路径] — [职责]
    ...

  需要验证的关联页面：
    1. [页面名] — [验证什么]
    ...
```

**关键原则：** 如果关联分析发现改动波及面过大，暂停并与团队讨论方案。小需求改出大动静通常意味着方案有问题。
